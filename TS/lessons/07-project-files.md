# Урок №7. `main.ts` и разделение TypeScript-проекта по файлам

Статус: **не завершён**.

## Цель урока

После урока нужно уметь:

- объяснить роль `main.ts`;
- вынести типы и функции в отдельные файлы;
- экспортировать данные через `export`;
- подключать их через `import`;
- выбирать понятную структуру небольшого проекта;
- собирать TypeScript из `src` в `dist`.

## 1. Зачем делить проект по файлам

Пока программа маленькая, весь код может находиться в одном файле:

~~~text
TS/
└── main.ts
~~~

Когда появляются типы, функции, классы и работа с данными, один файл становится трудно читать. Код делят по ответственности:

~~~text
TS/
└── src/
    ├── main.ts
    ├── types.ts
    └── calculations.ts
~~~

- `main.ts` запускает программу и связывает её части;
- `types.ts` хранит описания типов;
- `calculations.ts` хранит функции вычислений.

## 2. Что такое `main.ts`

`main.ts` обычно используют как входную точку программы. В нём не нужно хранить всю логику. Его задача:

1. Подключить нужные части программы.
2. Создать первоначальные данные или объекты.
3. Вызвать функции, которые запускают работу приложения.

Само имя `main.ts` не обладает особой силой TypeScript. Входным его делает способ запуска или настройки проекта.

## 3. `export`: разрешаем использовать код в другом файле

Файл `math.ts`:

~~~ts
export function add(first: number, second: number): number {
    return first + second;
}
~~~

Слово `export` делает функцию доступной для импорта из другого файла.

Без `export` функция остаётся внутренней частью файла.

Экспортировать можно функции, типы, интерфейсы, классы и переменные:

~~~ts
export type UserId = number | string;

export interface User {
    id: UserId;
    name: string;
}
~~~

## 4. `import`: подключаем код

Файл `main.ts`:

~~~ts
import { add } from "./math";

const result = add(10, 5);
console.log(result);
~~~

Путь `./math` означает:

- `.` — текущая папка;
- `/math` — файл `math.ts` в этой папке.

Для перехода на одну папку выше используется `..`:

~~~ts
import { User } from "../types";
~~~

## 5. Именованный экспорт

В одном файле можно экспортировать несколько сущностей:

~~~ts
export function add(first: number, second: number): number {
    return first + second;
}

export function subtract(first: number, second: number): number {
    return first - second;
}
~~~

Импортируются они в фигурных скобках и под теми же именами:

~~~ts
import { add, subtract } from "./math";
~~~

Имя можно изменить через `as`:

~~~ts
import { add as sum } from "./math";
~~~

На начальном этапе используй преимущественно именованные экспорты: по импорту сразу видно настоящее имя сущности.

## 6. Экспорт типов через `import type`

Файл `types.ts`:

~~~ts
export type Game = {
    title: string;
    price: number;
};
~~~

Файл `main.ts`:

~~~ts
import type { Game } from "./types";

const game: Game = {
    title: "Rust",
    price: 2500
};
~~~

`import type` подчёркивает, что импорт нужен только TypeScript для проверки типов. После преобразования в JavaScript тип исчезнет.

## 7. Экспорт по умолчанию

Файл может иметь один `default export`:

~~~ts
export default function start(): void {
    console.log("Программа запущена");
}
~~~

При импорте фигурные скобки не используются:

~~~ts
import start from "./start";
~~~

Имя такого импорта можно выбрать самостоятельно. Чтобы структура проекта оставалась понятной, в этом курсе в основном используем именованные экспорты.

## 8. Первая структура проекта

Для учебных задач достаточно:

~~~text
TS/
├── src/
│   ├── main.ts
│   ├── types.ts
│   └── utils.ts
└── tsconfig.json
~~~

Когда проект станет больше:

~~~text
TS/
├── src/
│   ├── main.ts
│   ├── types/
│   │   ├── game.ts
│   │   └── transaction.ts
│   ├── utils/
│   │   └── price.ts
│   └── services/
│       └── transactionService.ts
└── tsconfig.json
~~~

- `types` — типы и интерфейсы;
- `utils` — небольшие переиспользуемые функции;
- `services` — логика конкретной предметной области;
- `main.ts` — сборка и запуск программы.

Не нужно создавать отдельный файл для каждой строки. Разделение должно упрощать поиск кода.

## 9. Настройка `tsconfig.json`

Пример для учебного проекта:

~~~json
{
    "compilerOptions": {
        "target": "ES2022",
        "module": "CommonJS",
        "rootDir": "./src",
        "outDir": "./dist",
        "strict": true
    },
    "include": ["src/**/*.ts"]
}
~~~

- `rootDir` — где находится исходный TypeScript;
- `outDir` — куда записывать JavaScript;
- `strict` — строгая проверка типов;
- `include` — какие TypeScript-файлы входят в проект.

Сборка:

~~~bash
npx tsc
~~~

Запуск собранной программы:

~~~bash
node dist/main.js
~~~

## 10. Как выполняется программа

Если запускается `main.ts`, TypeScript/JavaScript сначала загружает его импорты. Импортируемый файл также может загружать собственные зависимости.

~~~text
main.ts
├── импортирует types.ts
└── импортирует calculations.ts
~~~

Не стоит создавать циклическую зависимость:

~~~text
fileA.ts импортирует fileB.ts
fileB.ts импортирует fileA.ts
~~~

Она усложняет порядок загрузки и архитектуру. Общий тип или функцию лучше вынести в третий файл.

## 11. Как выбирать файл для кода

Задавай три вопроса:

1. Что делает этот код?
2. Кто должен его использовать?
3. Можно ли назвать файл так, чтобы назначение было понятно без открытия?

Примеры:

- `transaction.ts` — тип транзакции;
- `calculateBalance.ts` — расчёт баланса;
- `main.ts` — запуск программы.
